그런데 어느 날 미팅에서 엔지니어가 말했습니다.

“그건 컨텍스트 윈도우 문제예요.”

나는 자연스럽게 고개를 끄덕였지만, 사실 그 말이 정확히 무엇을 의미하는지 몰랐습니다. 도구는 사용할 수 있었지만 원리는 설명하지 못했습니다. 왜 대화가 길어지면 느려지는지, 왜 비용이 증가하는지, 모델은 왜 그럴듯한 거짓말을 하는지, 같은 요청이 왜 중복 처리될 수 있는지 알지 못했습니다.

그 상태로도 서비스는 만들 수 있습니다. 하지만 서비스를 만드는 것과 안정적으로 운영하는 것은 전혀 다른 일이었습니다. 사용자와 데이터가 늘어나자 동시 요청, 트랜잭션, 서버 장애, 데이터 복구 같은 문제를 더는 AI가 작성한 코드에만 맡길 수 없었습니다. 내가 만든 서비스라면 문제가 생겼을 때 최소한 구조를 이해하고 판단할 수 있어야 했습니다.

그래서 집에 있는 컴퓨터에 Ubuntu Linux를 설치하고 SQL 데이터베이스도 직접 깔아봤습니다. 화면 뒤에서 서버와 데이터베이스가 어떻게 연결되는지, 스키마와 트랜잭션이 어떤 역할을 하는지 하나씩 확인했습니다. 그제야 Commit과 Rollback, Lock과 Deadlock이 단순한 개발 용어가 아니라 실제 데이터를 안전하게 지키기 위한 약속이라는 것이 보이기 시작했습니다.

프롬프트를 잘 쓰는 것과 AI를 이해하는 것은 다릅니다

원리를 알면 AI를 사용하는 방식이 달라집니다. 컨텍스트 윈도우와 KV Cache를 이해하면 긴 대화에서 비용과 품질이 흔들리는 이유가 보입니다. RLHF와 정렬을 이해하면 모델이 왜 특정한 방식과 말투로 답하도록 학습됐는지 알 수 있습니다. 스케일링 법칙과 추론 모델을 이해하면 모델의 성능이 어디에서 오고, 다음 세대의 AI가 어느 방향으로 발전할지 생각할 수 있습니다. 프롬프트를 잘 작성하는 것과 모델의 구조를 이해한 상태에서 사용하는 것은 다른 차원의 일입니다.

이 가이드는 2013년 word2vec부터 2025년 DeepSeek-R1까지, 현대 LLM의 발전에 중요한 역할을 한 논문 19편을 발표 순서와 개념의 의존관계에 따라 배치한 학습 로드맵입니다. 수식을 증명하는 것보다 각 논문이 다음 질문에 어떻게 답했는지를 이해하는 데 집중했습니다.

  • 이전 기술에는 어떤 한계가 있었을까?
  • 무엇을 새롭게 해결했을까?
  • 지금 사용하는 LLM에는 어떻게 남아 있을까?
  • 실제 제품을 만들 때 어디에 적용할 수 있을까?

어려운 개념은 탑다운 방식으로 쪼갰습니다. 그래도 이해되지 않으면 다시 한 단계 더 쪼개고, 비유와 구조도로 다시 설명했습니다. 수식의 문턱은 낮췄지만 최종 목적지는 논문 원문입니다. 순서대로 따라가면 서로 떨어져 있던 19편의 논문이 오늘날의 LLM으로 이어지는 하나의 이야기로 연결됩니다.

한 줄 요약: 파라미터의 3분의 2를 차지하는 FFN층이 사실 "패턴 → 다음 단어 예측" 사전이라는 발견입니다.

무엇이 문제였나? o1처럼 깊게 추론하는 모델을 만드는 방법은 공개되지 않았습니다. 사람이 쓴 풀이 데이터 없이도 가능할까?

핵심 아이디어 R1-Zero: SFT 없이, 수학·코드처럼 정답을 기계적으로 채점할 수 있는 문제에 GRPO 강화학습만 적용합니다. 그러자 학습이 진행되며 사고 길이가 저절로 길어지고, 스스로 검산하고 되돌아가는 'aha moment'가 나타났습니다.

실제 결과 AIME 수학경시 pass@1이 15.6% → 71.0%로, 다수결로는 86.7%까지 올라 o1-0912급이 되었습니다. 이를 다듬은 R1은 AIME 79.8%, MATH-500 97.3%로 o1-1217과 대등했고, 그 능력을 작은 모델들로 증류(distillation)해 공개했습니다.

읽을 때 주목 §2.2(규칙 기반 보상, 'aha'와 길이 증가 그래프)와 §2.4(증류)가 핵심입니다. GRPO 정의가 낯설면 DeepSeekMath §4를 먼저 보세요.

✦ 컴퓨터·하드웨어 기초 14

GPU★☆☆☆☆

그래픽 처리 장치. 수천 개의 단순 계산을 동시에 수행하는 칩으로, 행렬 곱셈에 특화되어 있어 AI 학습과 추론의 표준 하드웨어가 되었습니다. CPU가 소수의 똑똑한 일꾼이라면 GPU는 수천 명의 단순 작업 일꾼입니다.

병렬화 (parallelism)★★☆☆☆

여러 계산을 동시에 처리하는 것. 문장을 한 단어씩 순서대로 처리하던 RNN과 달리 Transformer는 모든 단어를 동시에 처리할 수 있어서 GPU를 최대로 활용합니다. Week 2의 핵심 키워드.

메모리 (VRAM/HBM)★★☆☆☆

GPU에 붙어 있는 작업 공간. 모델의 파라미터와 계산 중간값을 여기에 올려놓고 작업하므로, GPU 메모리 크기가 돌릴 수 있는 모델 크기의 상한을 정합니다.

SRAM★★★☆☆

GPU 칩 내부의 아주 작지만 매우 빠른 메모리. 크고 느린 HBM과 대비됩니다. FlashAttention은 데이터를 SRAM에 올려놓고 최대한 재사용해서 속도를 얻습니다.

메모리 대역폭 (memory bandwidth)★★★☆☆

메모리와 연산 장치 사이에 데이터가 오가는 속도. 도로의 차선 수에 비유할 수 있습니다. LLM 추론에서는 계산 속도보다 이 이동 속도가 병목인 경우가 많습니다.

memory-bound / compute-bound★★★★☆

작업의 병목이 어디에 있는가. 계산 자체가 오래 걸리면 compute-bound, 데이터를 실어 나르는 데 시간이 더 걸리면 memory-bound입니다. 토큰을 하나씩 생성하는 decode는 대표적인 memory-bound 작업입니다 (Week 6).

캐시 (cache)★☆☆☆☆

자주 쓰는 데이터를 가깝고 빠른 곳에 복사해 두는 것. 책상 서랍에 자주 쓰는 문구를 두는 것과 같습니다. KV cache, prefix cache 등 이 수업 전반에 등장합니다.

FLOPs★★★☆☆

부동소수점 연산 횟수(FLoating-point OPerations). '계산량'의 단위입니다. 모델 학습에 얼마나 많은 계산이 들었는지를 FLOPs로 표현합니다.

IO★★☆☆☆

데이터 입출력, 즉 데이터를 메모리에서 읽고 쓰는 이동 자체. FlashAttention(Week 7)의 핵심 통찰은 'attention의 병목은 계산(FLOPs)이 아니라 IO'라는 것입니다.

정밀도 (FP32/FP16/FP8/FP4, int8)★★★☆☆

숫자 하나를 몇 비트로 저장하는가. FP32는 정밀하지만 무겁고, FP8·FP4·int8처럼 줄이면 메모리와 속도가 크게 이득이지만 정확도가 떨어질 위험이 있습니다. 양자화(Week 11)의 기반 개념.

지연시간 / 처리량 (latency / throughput)★★☆☆☆

지연시간은 요청 하나가 끝날 때까지 걸리는 시간, 처리량은 단위 시간에 처리하는 총량. 서빙 시스템은 이 둘을 맞바꾸며 설계합니다.

wall-clock time★★☆☆☆

벽시계로 잰 실제 경과 시간. 계산량이 같아도 병렬화나 speculative decoding으로 실제 기다리는 시간은 줄일 수 있습니다.

커널 (kernel)★★★★☆

GPU에서 실행되는 작은 프로그램 단위. FlashAttention은 attention 계산 전체를 하나의 효율적인 커널로 다시 짠 것입니다.

벡터 · 행렬 · 텐서★★☆☆☆

숫자를 한 줄로 늘어놓으면 벡터, 표로 만들면 행렬, 그 이상 다차원이면 텐서. 딥러닝의 모든 데이터와 계산은 이 형태로 표현됩니다.

✦ 머신러닝 기초 16

머신러닝 / 딥러닝★☆☆☆☆

규칙을 사람이 짜는 대신 데이터에서 패턴을 스스로 찾게 하는 방법이 머신러닝, 그중 여러 층의 신경망을 쓰는 것이 딥러닝입니다.

신경망 (neural network)★☆☆☆☆

숫자를 받아 곱하고 더하는 단순한 계산 단위를 층층이 쌓은 함수. 층을 지날수록 점점 추상적인 특징을 잡아냅니다.

파라미터 / 가중치 (parameter)★★☆☆☆

모델 내부의 조절 가능한 숫자들. 학습이란 이 숫자들을 데이터에 맞게 조정하는 과정입니다. '7B 모델'은 파라미터가 70억 개라는 뜻입니다.

학습 vs 추론 (training vs inference)★☆☆☆☆

학습은 파라미터를 조정해 모델을 만드는 단계(비싸고 오래 걸림), 추론은 완성된 모델을 실제로 사용해 답을 생성하는 단계입니다. 이 수업 후반부는 추론을 얼마나 싸고 빠르게 하느냐를 다룹니다.

손실 함수 (loss)★★☆☆☆

모델의 답이 정답에서 얼마나 틀렸는지를 하나의 숫자로 나타낸 것. 학습은 이 숫자를 줄이는 방향으로 진행됩니다.

경사하강법 / 역전파 (gradient descent / backprop)★★★☆☆

손실이 줄어드는 방향(경사)을 계산해 파라미터를 조금씩 옮기는 방법과, 그 방향을 신경망 전체에 효율적으로 계산해 주는 알고리즘.

학습률 (learning rate)★★☆☆☆

파라미터를 한 번에 얼마나 옮길지 정하는 보폭. 너무 크면 발산하고 너무 작으면 느립니다. LoRA 논쟁(Week 11)에도 등장하는 실무 핵심 변수.

배치 (batch)★★☆☆☆

여러 데이터를 묶어 한 번에 처리하는 단위. GPU는 묶어서 처리할수록 효율이 좋습니다.

과적합 / 일반화 (overfitting / generalization)★★☆☆☆

훈련 데이터는 다 맞히는데 새 데이터에서 못하는 상태가 과적합, 처음 보는 데이터에서도 잘하는 능력이 일반화입니다.

사전학습 (pretraining)★★☆☆☆

방대한 인터넷 텍스트로 '다음 토큰 맞히기'를 시켜 언어의 일반 지식을 먼저 배우게 하는 단계. 이후 모든 능력의 토대가 됩니다.

파인튜닝 (fine-tuning)★★☆☆☆

사전학습된 모델을 특정 목적의 적은 데이터로 추가 학습시키는 것. 전체 파라미터를 다 조정하면 full fine-tuning, 일부만 조정하면 LoRA 같은 방식입니다.

SFT (supervised fine-tuning)★★★☆☆

'질문-모범답안' 쌍을 주고 모범답안을 따라 하도록 파인튜닝하는 것. RLHF 파이프라인(Week 9)의 첫 단계입니다.

임베딩 (embedding)★★★☆☆

단어나 문장의 의미를 숫자 벡터(공간 위의 좌표)로 바꾼 것. 의미가 비슷하면 좌표도 가깝습니다. word2vec(Week 1)이 이 아이디어의 출발점.

소프트맥스 (softmax)★★★☆☆

여러 점수를 합이 1인 확률로 바꾸는 함수. 다음 토큰 선택과 attention 가중치 계산 양쪽에 쓰입니다.

ablation (절제 실험)★★★☆☆

모델에서 부품 하나를 빼거나 바꿔 보고 성능 변화를 재는 실험. 논문에서 '이 부품이 정말 중요했는가'를 증명하는 표준 방법입니다.

벤치마크 (benchmark)★☆☆☆☆

모델들을 같은 문제집으로 시험 봐서 비교하는 표준 평가 세트. 후반부(Packet 4)에서는 벤치마크 자체의 신뢰성을 비판적으로 봅니다.

✦ 언어모델과 토큰 13

언어모델 (LM)★☆☆☆☆

'지금까지의 글 다음에 올 단어'의 확률을 계산하는 모델. ChatGPT류의 본질은 아주 잘하는 다음 단어 예측기입니다.

LLM (대규모 언어모델)★☆☆☆☆

파라미터 수십억~수조 개 규모로 키운 언어모델. 규모가 커지면서 번역, 코딩, 추론 같은 능력이 생겨났습니다.

토큰 (token)★☆☆☆☆

모델이 글을 처리하는 최소 단위. 단어보다 작을 수 있습니다(예: '먹었다' → '먹', '었다'). 요금과 속도, 컨텍스트 길이가 모두 토큰 단위로 계산됩니다.

토크나이저 / BPE★★★☆☆

글을 토큰으로 쪼개는 도구와 그 대표 알고리즘(Byte Pair Encoding). 자주 나오는 글자 조합을 병합해 어휘를 만듭니다. GPT-2(Week 2)부터 표준.

next-token prediction★★☆☆☆

다음 토큰 하나를 맞히는 과제. 이 단순한 과제를 인터넷 규모로 풀게 했더니 언어 능력 전반이 생겼다는 것이 LLM의 핵심 스토리입니다.

autoregressive (자기회귀)★★★☆☆

자기가 방금 생성한 토큰을 다시 입력에 넣어 다음 토큰을 만드는 방식. 한 글자씩 이어 쓰는 릴레이 소설과 같고, 그래서 생성은 본질적으로 순차적(느림)입니다.

컨텍스트 윈도우 (context window)★★☆☆☆

모델이 한 번에 볼 수 있는 토큰 수의 한계. 모델의 '작업 기억' 크기입니다. 이를 늘리는 기법이 Week 5(RoPE 확장)의 주제.

프롬프트 (prompt)★☆☆☆☆

모델에 넣는 입력 텍스트 전체. 지시문, 예시, 자료가 모두 포함됩니다.

zero-shot / few-shot★★☆☆☆

예시 없이 지시만으로 시키면 zero-shot, 예시 몇 개를 프롬프트에 넣어 주면 few-shot입니다. GPT-3(Week 2)가 이 능력을 유명하게 만들었습니다.

in-context learning (ICL)★★★☆☆

파라미터를 바꾸지 않고, 프롬프트 안의 예시만 보고 그 자리에서 패턴을 흉내 내는 능력. induction head(Week 3)가 그 내부 메커니즘 후보입니다.

n-gram★★★☆☆

직전 n개 단어만 보고 다음 단어를 세는 고전적 통계 기법. 신경망 언어모델(Bengio 2003, Week 1)이 이것의 한계(희소성)를 풀면서 역사가 시작됩니다.

perplexity★★★★☆

모델이 텍스트를 얼마나 '덜 놀라며' 예측하는지 나타내는 지표. 낮을수록 언어를 잘 모델링한다는 뜻입니다.

needle in a haystack★★☆☆☆

긴 문서(건초더미) 속에 숨긴 문장(바늘)을 찾게 하는 긴 컨텍스트 시험. NoLiMa(Week 5)는 이 시험이 단어 겹침에 의존하면 부풀려진다는 것을 보입니다.

✦ Transformer 내부 15

Transformer★★☆☆☆

2017년 'Attention Is All You Need'가 제안한 구조. 순환(RNN) 없이 attention만으로 문맥을 처리해 병렬화가 가능해졌고, 현재 거의 모든 LLM의 뼈대입니다.

attention★★☆☆☆

문장 안의 각 단어가 다른 단어들을 얼마나 참조할지 가중치를 매기는 메커니즘. '그것'이라는 단어가 앞의 어떤 명사를 가리키는지 연결하는 식입니다.

Q / K / V (query, key, value)★★★★☆

attention의 세 재료. 각 단어가 '무엇을 찾는지(Q)', '자신이 무엇인지 알리는 표지(K)', '실제로 전달할 내용(V)'입니다. Q와 K를 맞춰보고 잘 맞는 곳의 V를 가져옵니다.

multi-head attention★★★☆☆

attention을 여러 개(head) 병렬로 두어 각각 다른 관계(문법, 지시, 위치 등)를 보게 하는 것.

FFN / MLP★★★☆☆

Transformer 블록에서 attention 다음에 오는 층. Week 3 필수 논문은 이 층을 '패턴을 감지하는 key와 지식을 꺼내는 value의 저장소'로 해석합니다.

residual stream (잔차 흐름)★★★★☆

각 층이 결과를 덮어쓰지 않고 원래 입력에 '더해 가는' 통로. 정보가 흐르는 중앙 컨베이어 벨트로, 해석가능성 연구(Week 3)의 기본 어휘입니다.

LayerNorm / RMSNorm★★★★☆

각 층의 숫자 크기를 일정 범위로 맞춰 학습을 안정시키는 정규화. RMSNorm은 평균 빼기를 생략한 경량판으로 현대 LLM의 표준입니다.

위치 인코딩 (positional encoding)★★★☆☆

attention 자체는 단어 순서를 모르므로, '몇 번째 단어인지' 정보를 따로 넣어 주는 장치입니다.

RoPE (rotary position embedding)★★★★☆

단어 벡터를 위치에 따라 '회전'시켜 순서 정보를 넣는 방식(Week 5). 두 단어 사이의 상대 거리가 자연스럽게 표현되어, 컨텍스트 확장 기법들의 공통 기반이 됩니다.

encoder / decoder / decoder-only★★★☆☆

입력을 이해하는 쪽이 encoder, 출력을 생성하는 쪽이 decoder. BERT는 encoder만, GPT는 decoder만 씁니다. 현대 LLM은 대부분 decoder-only입니다.

attention head★★★☆☆

multi-head attention의 head 하나. 해석가능성 연구는 특정 head가 특정 역할(예: 패턴 복사)을 맡는 것을 발견했습니다.

induction head★★★★★

'A B ... A' 다음에 'B'를 예측하는, 패턴을 복사하는 head 회로(Week 3). in-context learning의 내부 메커니즘으로 지목됩니다.

attention sink★★★★★

많은 head가 첫 토큰에 attention을 쏟아붓는 현상. 쓸모없어 보이지만 정보가 과도하게 섞이는 것을 막는 안전판이라는 해석이 있습니다(Week 3, 2025).

circuit (회로)★★★★★

모델 내부에서 특정 기능을 수행하는 부품들의 연결. 모델을 블랙박스가 아니라 분해 가능한 기계로 보는 해석가능성 연구의 핵심 개념입니다.

logits★★★☆☆

확률로 바뀌기 전의 원점수. 모델의 마지막 출력이며, 여기에 softmax를 적용하면 다음 토큰 확률이 됩니다.

✦ 추론(서빙)과 효율화 21

prefill vs decode★★★★☆

prefill은 프롬프트 전체를 한 번에 읽는 단계(병렬, 계산 위주), decode는 토큰을 하나씩 생성하는 단계(순차, 메모리 위주). 성격이 달라 최적화 방법도 다릅니다(Week 6).

KV cache★★★☆☆

이미 처리한 토큰들의 K와 V를 저장해 두는 캐시. 매 토큰마다 앞부분을 다시 계산하지 않게 해 주지만, 대화가 길어질수록 GPU 메모리를 크게 차지합니다. 서빙 비용의 핵심.

샘플링 (sampling)★★☆☆☆

다음 토큰을 확률에 따라 '뽑는' 것. 항상 1등만 고르면(greedy) 반복적이고 지루한 글이 되므로 적절한 무작위성을 넣습니다(Week 6).

temperature★★☆☆☆

샘플링의 모험 수위 조절 손잡이. 낮으면 안전하고 뻔한 선택, 높으면 다양하지만 위험한 선택을 합니다.

top-p / min-p / typical sampling★★★☆☆

확률이 낮은 꼬리 토큰들을 잘라내고 뽑는 방법들. top-p는 누적 확률 상위만, min-p는 1등 대비 일정 비율 이상만 남깁니다.

speculative decoding (추측 디코딩)★★★★☆

작고 빠른 모델이 여러 토큰을 초안으로 쓰고, 큰 모델이 한 번에 검증하는 기법. 출력 분포가 수학적으로 동일하게 유지되면서 실제 시간만 줄어듭니다(Packet 2).

draft model★★★★☆

speculative decoding에서 초안을 쓰는 작은 모델. 초안이 잘 맞을수록(acceptance rate) 가속이 커집니다.

FlashAttention★★★★☆

attention을 타일 단위로 쪼개 빠른 SRAM 안에서 처리해 IO를 최소화한 구현(Week 7). 근사가 아니라 정확히 같은 결과를 더 빠르게 냅니다.

tiling / online softmax★★★★★

큰 행렬을 작은 타일로 나눠 처리하는 기법과, 전체를 다 보지 않고도 softmax를 점진적으로 계산하는 트릭. FlashAttention의 두 재료입니다.

MQA / GQA★★★★☆

여러 attention head가 K·V를 공유해 KV cache를 줄이는 기법. MQA는 전부 공유, GQA는 그룹별 공유(산업 표준 타협안)입니다(Week 7).

PagedAttention★★★★☆

운영체제의 페이징처럼 KV cache를 작은 블록으로 나눠 관리하는 vLLM의 기법. 메모리 낭비(단편화)를 줄여 같은 GPU로 더 많은 요청을 처리합니다.

prefix caching / RadixAttention★★★★☆

여러 요청이 공유하는 프롬프트 앞부분(예: 시스템 프롬프트)의 KV cache를 재사용하는 기법. API의 'context caching' 할인이 이 원리입니다.

KV cache 압축 / eviction★★★★★

오래되거나 덜 중요한 토큰의 KV를 버리거나(H2O, SnapKV) 낮은 정밀도로 저장해 메모리를 아끼는 기법. 무엇이 조용히 사라지는지가 쟁점입니다(Week 7).

양자화 (quantization)★★★☆☆

파라미터를 낮은 정밀도(8bit, 4bit)로 저장해 모델을 가볍게 만드는 것. 책을 요약본으로 바꿔 책장을 늘리는 셈이며, 품질 손실을 최소화하는 것이 기술입니다(Week 11).

outlier (이상치 활성값)★★★★☆

일부 채널에서 유난히 큰 값. 6.7B 이상 모델에서 갑자기 나타나 단순한 양자화를 망가뜨리며, LLM.int8()·AWQ 등이 이를 우회하는 설계입니다.

LoRA / low-rank / rank★★★☆☆

전체 파라미터 대신 작은 보조 행렬 두 개(A×B)만 학습하는 효율적 파인튜닝(Week 11). rank는 그 보조 행렬의 '폭'으로, 표현력과 비용을 조절합니다.

QLoRA★★★★☆

모델 본체는 4bit로 양자화해 두고 LoRA만 학습하는 조합. 소비자용 GPU에서도 큰 모델을 파인튜닝할 수 있게 했습니다.

MoE (Mixture-of-Experts)★★★☆☆

FFN을 여러 '전문가'로 나누고 토큰마다 일부만 골라 쓰는 구조(Packet 1). 파라미터는 크게 늘리되 계산량은 유지합니다. 핵심 난제는 전문가들에게 일을 고르게 배분하는 routing.

routing / load balancing★★★★☆

MoE에서 각 토큰을 어느 전문가에게 보낼지 정하는 것과, 특정 전문가에게만 일이 몰리지 않게 하는 것. 해법이 보조 loss에서 bias 항으로 진화했습니다.

MTP (multi-token prediction)★★★★☆

한 번에 다음 여러 토큰을 예측하도록 학습하는 것. 모델 안에 draft 모델을 내장하는 효과가 있습니다(DeepSeek-V3).

서빙 (serving)★★☆☆☆

학습된 모델을 실제 서비스로 운영하는 일. 수많은 동시 요청을 GPU에 효율적으로 배치하는 시스템 엔지니어링입니다(Week 7).

✦ 학습·정렬 (alignment) 16

scaling law (스케일링 법칙)★★★☆☆

모델 크기·데이터·계산량을 늘리면 성능이 얼마나 좋아지는지의 경험 법칙(Week 9). '더 크게 만들면 얼마나 좋아지는가'를 예측 가능하게 만들었습니다.

Chinchilla / compute-optimal★★★★☆

같은 계산 예산이라면 모델 크기와 데이터 양을 어떻게 나눠야 최적인지에 대한 답(파라미터당 약 20 토큰). 이후 '추론 비용까지 고려하면?'이라는 반론이 이어집니다.

창발 (emergent ability)★★★☆☆

규모를 키우다 보면 어느 문턱에서 갑자기 나타나는 능력. CoT 추론(Week 13)이 대표 사례로 논의됩니다.

RLHF★★★☆☆

인간 피드백 기반 강화학습. 사람이 매긴 선호를 reward model로 학습시킨 뒤, 그 점수를 높이도록 모델을 조정합니다. ChatGPT를 만든 파이프라인(Week 9).

강화학습 (RL) / policy / reward★★★☆☆

시도하고 보상을 받으며 배우는 학습 방식. 행동을 정하는 모델이 policy, 잘했는지의 점수가 reward입니다.

reward model (RM)★★★☆☆

사람 대신 '이 답변이 더 좋다'를 판정하도록 학습된 채점 모델. RLHF에서 사람의 선호를 대리합니다.

PPO★★★★☆

RL 알고리즘의 표준(Week 8). 모델이 한 번에 너무 크게 변하지 않도록 업데이트 폭을 잘라내는(clip) 것이 핵심 아이디어입니다.

DPO★★★★☆

reward model과 RL 없이, 선호 쌍 데이터로 직접 파인튜닝하는 방법(Week 10). '당신의 언어모델은 사실 reward model이다'라는 수학적 재해석에서 나왔습니다.

GRPO★★★★★

같은 문제에 여러 답을 생성해 그룹 내 상대 비교로 학습하는 RL 변형. DeepSeek-R1(Week 13)의 추론 학습에 사용되었습니다.

KL divergence★★★★☆

두 확률분포가 얼마나 다른지의 척도. RLHF에서는 모델이 원래 모습에서 너무 멀어지지 않게 잡아 주는 고삐로 쓰입니다.

선호 쌍 (preference pair)★★☆☆☆

같은 질문에 대한 두 답변 중 '어느 쪽이 더 좋은가'를 표시한 데이터. RLHF와 DPO의 원료입니다.

Bradley-Terry 모델★★★★★

'A가 B를 이길 확률'을 두 실력 점수의 차이로 표현하는 고전 통계 모델. 선호 데이터에서 reward를 유도하는 수학적 기초입니다.

alignment (정렬)★★☆☆☆

모델의 행동을 인간의 의도와 가치에 맞추는 일. 유용하고, 정직하고, 무해하게 만드는 것이 목표입니다.

alignment tax★★★☆☆

정렬을 강하게 할수록 일부 능력 점수가 떨어지는 대가. InstructGPT 논문(Week 9)에서 관찰되었습니다.

reward hacking / overoptimization★★★☆☆

모델이 채점 기준의 허점을 파고들어 점수만 높이고 실제 품질은 망가지는 현상. 채점 모델을 과하게 믿으면 반드시 나타납니다(Week 9, 13).

distillation (증류)★★★☆☆

크고 강한 모델의 출력을 교재 삼아 작은 모델을 가르치는 것. R1의 추론 능력을 작은 모델로 옮기는 데 쓰였습니다(Week 13).

✦ Reasoning · 에이전트 · RAG 17

CoT (chain-of-thought)★★☆☆☆

답만 내지 말고 풀이 과정을 단계별로 쓰게 하는 프롬프트 기법(Week 13). 충분히 큰 모델에서 수학·논리 성능이 크게 오릅니다.

self-consistency★★★☆☆

같은 문제를 여러 번 풀게 한 뒤 다수결로 답을 고르는 기법. CoT와 짝을 이루는 Week 13 필수입니다.

reasoning model (추론 모델)★★☆☆☆

답하기 전에 길게 생각(사고 사슬 생성)하도록 RL로 학습된 모델. DeepSeek-R1, o1 계열이 대표입니다.

test-time compute / scaling★★★☆☆

학습이 아니라 '문제를 푸는 순간'에 계산을 더 쓰는 두 번째 성능 축(Packet 3). 여러 번 시도(parallel)하거나 더 오래 생각(sequential)하게 합니다.

PRM vs ORM★★★★★

풀이의 각 단계를 채점하면 PRM(process), 최종 답만 채점하면 ORM(outcome). 'Let's Verify Step by Step'(Week 13)의 핵심 비교입니다.

verifier / RLVR★★★★☆

답이 맞았는지 기계적으로 확인할 수 있는 채점기(수학 정답, 코드 테스트)와, 그 채점으로 하는 강화학습(RL with Verifiable Rewards). 불완전한 verifier는 편법(gaming)을 부릅니다.

에이전트 (agent)★☆☆☆☆

LLM이 도구를 호출하고 결과를 관찰하며 여러 단계에 걸쳐 스스로 작업을 진행하는 시스템(Week 12). 한 번 묻고 답하는 챗봇과 구별됩니다.

ReAct 루프★★★☆☆

생각(Thought) → 행동(Action) → 관찰(Observation)을 반복하는 에이전트의 표준 동작 구조. A2 과제에서 직접 구현합니다.

tool use (도구 사용)★★☆☆☆

LLM이 검색, 계산기, 코드 실행 같은 외부 기능을 호출하는 것. 모델의 출력이 '말'을 넘어 '행동'이 되는 지점입니다.

MCP (Model Context Protocol)★★★☆☆

모델과 외부 도구·데이터를 연결하는 표준 규약. 도구마다 제각각이던 연결 방식을 USB처럼 통일하려는 시도입니다(Week 12).

harness★★★☆☆

모델을 감싸는 실행 환경 전체 — 프롬프트, 도구 목록, 루프 제어, 평가까지. 2026년 관점에서는 성능 = 모델 × harness입니다(Week 12).

prompt injection (프롬프트 주입)★★☆☆☆

모델이 읽는 자료(웹페이지, 이메일) 안에 몰래 명령을 심어 에이전트를 조종하는 공격(Packet 5). 지시와 데이터가 같은 통로로 들어온다는 구조적 약점을 노립니다.

RAG (검색 증강 생성)★★☆☆☆

질문과 관련된 문서를 먼저 검색해 프롬프트에 넣어 주고 답하게 하는 구조(Packet 6). 모델이 모르는 최신·사내 정보를 다루는 표준 방법입니다.

retriever / chunk★★★☆☆

관련 문서를 찾아오는 검색 모듈과, 문서를 검색 가능한 크기로 자른 조각. 무엇을 어떻게 잘라 어떤 기준으로 찾느냐가 RAG 품질을 정합니다.

hallucination (환각)★☆☆☆☆

모델이 그럴듯하지만 사실이 아닌 내용을 자신 있게 지어내는 현상. RAG, verifier, 불확실성 정량화가 모두 이 문제와 싸우는 도구입니다.

rollout / trajectory★★★★☆

모델이나 에이전트가 한 번 끝까지 시도한 전체 기록. RL 학습과 에이전트 평가의 기본 단위입니다.

CoT faithfulness★★★★☆

모델이 보여주는 풀이 과정이 실제 내부 판단 과정과 일치하는가의 문제(Week 13). 힌트를 쓰고도 풀이에는 안 드러내는 사례가 보고되었습니다.

✦ 평가와 신뢰성 7

pass@k / pass^k★★★★☆

k번 시도해서 한 번이라도 성공하면 인정(pass@k) vs k번 모두 성공해야 인정(pass^k). 전자는 잠재력, 후자는 신뢰성을 잽니다(Packet 4).

contamination (오염)★★★☆☆

시험 문제가 모델의 학습 데이터에 이미 들어가 있어 점수가 부풀려지는 문제. 벤치마크 신뢰성 논쟁의 단골 원인입니다.

SWE-bench★★★☆☆

실제 GitHub 이슈를 고치게 하는 코딩 에이전트 벤치마크(Packet 4 anchor). 테스트 통과 여부로 채점하며, 그 테스트의 허점 자체가 2026년 논쟁거리입니다.

calibration (보정)★★★★☆

모델이 말하는 자신감(확률)이 실제 정답률과 일치하는 정도. '90% 확신'이라 말한 것들이 실제로 90% 맞아야 잘 보정된 것입니다.

conformal prediction★★★★★

어떤 모델이든 '정답이 이 안에 있을 확률 90% 보장' 같은 통계적 보장을 붙여 주는 기법. 의료 등 고위험 분야 배포의 기초 도구입니다(후속 주제).

불확실성 정량화 (uncertainty quantification)★★★★☆

모델이 스스로 '얼마나 모르는지'를 수치로 내놓게 하는 연구. semantic entropy는 표현이 아니라 의미 수준의 불확실성으로 환각을 탐지합니다.

절대평가 / 상대평가★☆☆☆☆

이 수업은 절대평가 — 다른 학생과의 경쟁이 아니라 기준 충족 여부로 성적이 결정됩니다.

✦ 논문 속 용어 — 원문 연결 45

beam search (빔 서치)★★★☆☆

가장 확률 높은 한 갈래만 따라가지 않고, 유망한 문장 후보 몇 개를 동시에 끌고 가며 최선을 고르는 생성 방법입니다. 번역 모델의 표준 디코딩이었습니다. → 원문: Attention Is All You Need

BLEU (블루 점수)★★★☆☆

기계번역 품질을 정답 번역과의 n-gram 겹침으로 자동 채점하는 지표입니다. Transformer의 28.4가 이 점수입니다. → 원문: Attention Is All You Need

label smoothing (라벨 스무딩)★★★★☆

정답에 100% 확신하도록 가르치지 않고 정답 확률을 살짝 깎아 과신을 막는 학습 트릭입니다. → 원문: Attention Is All You Need

dropout (드롭아웃)★★★☆☆

학습 중 뉴런 일부를 무작위로 꺼서, 특정 뉴런에 과하게 의존하는 과적합을 막는 기법입니다. → 원문: Attention Is All You Need

warmup (웜업)★★★☆☆

학습 초반에 학습률을 서서히 올렸다가 내리는 스케줄입니다. Transformer 학습 안정화의 필수 요소였습니다. → 원문: Attention Is All You Need

WMT (번역 벤치마크)★★☆☆☆

기계번역 학회의 표준 번역 데이터셋·대회입니다. 'WMT14 영-독'처럼 연도·언어쌍으로 부릅니다. → 원문: Attention Is All You Need

hierarchical softmax (계층적 소프트맥스)★★★★★

수십만 단어 전체에 대한 확률 계산을 이진 트리 탐색으로 바꿔, 어휘 크기의 로그 수준으로 줄이는 고속화 기법입니다. → 원문: word2vec

bidirectional RNN (양방향 RNN)★★★★☆

문장을 앞→뒤, 뒤→앞 두 방향으로 읽어 각 단어에 양쪽 문맥을 담는 순환 신경망입니다. → 원문: Bahdanau attention

GRU (게이트 순환 유닛)★★★★☆

무엇을 기억하고 잊을지 게이트로 조절하는 경량 순환 유닛입니다. 이 논문 계열에서 제안되어 LSTM의 대안이 되었습니다. → 원문: Bahdanau attention

annotation (주석 벡터)★★★★☆

Bahdanau 인코더가 소스 단어마다 만드는 문맥 담긴 벡터로, attention이 참조하는 대상입니다. → 원문: Bahdanau attention

rotation matrix (회전 행렬)★★★☆☆

벡터를 일정 각도만큼 돌리는 행렬입니다. RoPE는 위치를 이 회전 각도로 인코딩합니다. → 원문: RoFormer

linear attention (선형 어텐션)★★★★★

softmax를 근사해 계산량을 시퀀스 길이에 선형으로 줄인 attention 변형입니다. RoPE는 여기에도 장착됩니다. → 원문: RoFormer

long-term decay (장거리 감쇠)★★★★☆

두 토큰이 멀수록 attention 상호작용이 자연히 약해지는 성질로, RoPE가 증명한 장점입니다. → 원문: RoFormer

TPU (텐서 처리 장치)★★☆☆☆

Google이 만든 AI 전용 칩입니다. PaLM 서빙 분석은 TPU v4 기준으로 이뤄졌습니다. → 원문: Scaling Inference

partitioning (모델 분할)★★★★☆

모델 하나를 여러 칩에 나눠 싣는 방법입니다. 어떻게 자르느냐가 통신량과 지연을 좌우합니다. → 원문: Scaling Inference

recomputation (재계산)★★★★☆

역전파 때 필요한 중간값을 저장해 두는 대신 그때그때 다시 계산해 메모리를 아끼는 기법입니다. FlashAttention 역전파의 핵심입니다. → 원문: FlashAttention

trust region (신뢰 영역)★★★★★

현재 정책 근처의 '믿을 수 있는 범위' 안에서만 업데이트를 허용하는 개념입니다. PPO는 이를 clip으로 단순화했습니다. → 원문: PPO

advantage (어드밴티지)★★★★☆

이 행동이 평균적인 행동보다 얼마나 더 좋았는지의 상대 점수입니다. 정책 경사의 방향을 정합니다. → 원문: PPO

GAE (일반화 어드밴티지 추정)★★★★★

어드밴티지를 편향과 분산 사이에서 절충해 추정하는 표준 기법입니다. → 원문: PPO

entropy bonus (엔트로피 보너스)★★★★☆

정책이 한 가지 행동으로 너무 빨리 굳지 않도록 다양성에 주는 보상입니다. → 원문: PPO

epoch (에폭)★★☆☆☆

같은 데이터 전체를 한 바퀴 도는 단위입니다. PPO는 같은 데이터로 여러 에폭 업데이트할 수 있는 것이 장점입니다. → 원문: PPO

learning rate schedule (학습률 스케줄)★★★☆☆

학습 진행에 따라 학습률을 낮추는 계획입니다. Chinchilla는 이 스케줄을 토큰 수에 맞추자 기존 결론이 뒤집혔습니다. → 원문: Chinchilla

MMLU (종합 지식 벤치마크)★★☆☆☆

57개 과목의 객관식 시험으로 모델의 폭넓은 지식을 재는 표준 벤치마크입니다. Chinchilla가 67.5%로 기록을 세웠습니다. → 원문: Chinchilla

power law (거듭제곱 법칙)★★★☆☆

한 변수를 10배 하면 다른 변수가 일정 배율로 변하는 관계로, 로그 그래프에서 직선이 됩니다. 스케일링 법칙의 수학적 형태입니다. → 원문: Kaplan scaling laws

labeler (라벨러)★☆☆☆☆

모델 답변을 쓰거나 순위 매기는 사람 평가자입니다. InstructGPT는 약 40명의 검증된 라벨러를 썼습니다. → 원문: InstructGPT

TruthfulQA (진실성 벤치마크)★★☆☆☆

사람들이 흔히 속는 질문으로 모델이 거짓 통념을 말하는지 재는 평가입니다. → 원문: InstructGPT

toxicity (유해성)★☆☆☆☆

모욕·혐오 등 해로운 출력의 정도입니다. RealToxicityPrompts 같은 벤치마크로 잽니다. → 원문: InstructGPT

reference model (참조 모델)★★★☆☆

정렬 학습 중 '여기서 너무 멀어지지 말라'의 기준이 되는 고정된 원본 모델입니다. → 원문: DPO

win rate (승률 평가)★★☆☆☆

두 모델의 답변을 나란히 놓고 어느 쪽이 나은지의 비율로 비교하는 평가 방식입니다. → 원문: DPO

LLM-as-judge (모델 심판)★★☆☆☆

사람 대신 강한 모델(GPT-4 등)에게 답변 비교를 맡기는 평가 방법입니다. DPO 실험의 채점 방식입니다. → 원문: DPO

EMA (지수이동평균)★★★★☆

값을 서서히 따라가는 평균입니다. PPO의 참조 모델을 EMA로 갱신하는 것이 성능 요소로 밝혀졌습니다. → 원문: DPO vs PPO

CodeContests (코딩 대회 벤치마크)★★☆☆☆

프로그래밍 대회 문제로 모델을 평가하는 어려운 벤치마크입니다. PPO 34B가 여기서 기록을 세웠습니다. → 원문: DPO vs PPO

adapter (어댑터)★★★☆☆

얼린 모델 사이사이에 끼워 넣는 작은 학습 모듈입니다. 효과적이지만 추론이 느려져, LoRA가 이를 대체했습니다. → 원문: LoRA

prefix tuning (프리픽스 튜닝)★★★★☆

학습 가능한 가상 토큰을 프롬프트 앞에 붙이는 적응 기법입니다. 컨텍스트를 잡아먹는 단점이 있습니다. → 원문: LoRA

absmax quantization (절댓값 최대 양자화)★★★★☆

한 묶음의 최댓값을 기준으로 눈금을 맞춰 8비트로 바꾸는 기본 양자화입니다. 이상치 하나가 눈금을 망치는 약점이 있습니다. → 원문: LLM.int8()

vector-wise quantization (벡터 단위 양자화)★★★★☆

행·열 단위로 따로 눈금을 매겨 정밀도 낭비를 줄이는 양자화입니다. LLM.int8()의 1단계입니다. → 원문: LLM.int8()

checkpoint (체크포인트)★★☆☆☆

학습된 모델 가중치를 저장한 파일입니다. '175B 체크포인트를 변환해 즉시 사용'처럼 씁니다. → 원문: LLM.int8()

imitation learning (모방학습)★★★☆☆

전문가의 행동 기록을 그대로 따라 하도록 학습하는 방법입니다. ReAct는 1-2개 예시만으로 이를 이겼습니다. → 원문: ReAct

ALFWorld / WebShop (에이전트 벤치마크)★★☆☆☆

텍스트 집안일 시뮬레이터와 실제 상품 데이터 쇼핑 환경으로, 에이전트의 의사결정을 평가합니다. → 원문: ReAct

GSM8K (수학 문장제 벤치마크)★★☆☆☆

초등 수준 수학 문장제 8500문제로 다단계 추론을 재는 표준 벤치마크입니다. CoT 효과가 가장 극적으로 나타난 곳입니다. → 원문: Chain-of-Thought

symbolic reasoning (기호 추론)★★★☆☆

동전 던지기 추적, 단어 마지막 글자 잇기처럼 규칙 조작 능력을 보는 과제입니다. → 원문: Chain-of-Thought

reasoning path (추론 경로)★★☆☆☆

답에 도달하는 하나의 풀이 과정입니다. Self-Consistency는 여러 경로를 뽑아 답만 집계합니다. → 원문: Self-Consistency

cold start (콜드 스타트)★★★☆☆

본 학습 전에 소량의 정제 데이터로 기초를 잡아 주는 준비 단계입니다. R1이 R1-Zero의 가독성 문제를 고친 방법입니다. → 원문: DeepSeek-R1

rejection sampling (기각 샘플링)★★★★☆

여러 출력을 생성해 채점 후 좋은 것만 골라 데이터로 삼는 방법입니다. R1의 3단계에서 80만 건을 이렇게 만들었습니다. → 원문: DeepSeek-R1

AIME / MATH-500 (수학 경시 벤치마크)★★☆☆☆

미국 수학 경시(AIME)와 고난도 수학 500제로, 추론 모델의 대표 성적표입니다. → 원문: DeepSeek-R1
